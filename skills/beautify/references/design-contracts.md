# Beautify 设计执行契约

本文件用于把“风格名称”转化为 AI 可执行、可验收的界面改造要求。使用任一主题时，读取对应主题契约并严格执行；不得只改颜色。

## 通用执行契约

### 输入分析

先识别页面类型、用户目标、主要任务、数据密度和现有交互，再开始修改。把页面元素归入以下语义：

- 页面外壳：导航、侧栏、页头、内容区、页脚
- 信息概览：KPI、趋势、同比、进度、告警
- 数据主体：表格、列表、排行榜、图表
- 操作区域：筛选器、搜索、按钮、批量操作
- 流程状态：步骤、时间线、审批、任务状态
- 反馈层：弹窗、Toast、Alert、空状态、加载状态

### 结构重构规则

1. 保留业务数据、链接、表单字段、事件绑定、元素 id、`data-*` 属性和可访问性属性。
2. 将零散数字重构为 `.stat-card`；将状态重构为 `.badge`；将流程重构为 `.steps-wrap`；将百分比重构为 `.progress-bar`。
3. 不为装饰把所有列表强行改成排行榜。只有存在排名、绩效、Top N 语义时才使用 `.leaderboard-list`。
4. 使用 8px 基础间距网格，建立页面、区域、组件和元素四级间距，不允许随机 margin。
5. 建立明确层级：页面标题 > 区块标题 > 核心值 > 标签 > 辅助说明。
6. 每个主要区域至少同时优化结构、排版、颜色、边框/阴影和交互状态五个层面。
7. 保持响应式：桌面多列、窄屏自动降列；禁止固定宽度造成横向溢出。
8. 作用域限制在 `.beautify-root` 内，不覆盖宿主系统全局样式。
9. 主题切换采用 replace-not-stack：新主题写入前必须卸载旧主题 CSS、脚本、装饰 DOM、根主题类、框架 import 和主题专属组件外壳；业务 DOM 与业务逻辑保留。
10. 页面最终只能存在一个 `data-beautify-theme` / `beautify-theme-*` 当前主题标识，不得同时加载多个主题 CSS 或保留非当前主题动态锚点。

### 主题迁移清单

- CSS：删除旧 `<style data-beautify>`、旧主题 CSS import、重复 Token 与后置覆盖。
- JS：删除旧 `data-beautify-script`、Canvas 初始化、事件监听入口和动态库导入。
- DOM/JSX：删除旧主题纯装饰节点；旧主题专属业务外壳需迁移为新主题结构，不能简单隐藏。
- 根节点：移除所有旧 `beautify-theme-*`，仅保留 `beautify-theme-<当前主题ID>` 与 `data-beautify-theme`。
- 颜色残留：运行 `node scripts/audit-theme-residue.js <项目源码目录> <当前主题ID>`，逐条处理旧 HEX、Tailwind 蓝色类和旧主题 class；残留为 0 才能通过。
- 嵌套元素：运行 `node scripts/audit-nested-components.js <项目源码目录>`，逐层检查父容器、子胶囊、链接容器、按钮、Badge、Tag、文字、背景、边框及 hover/focus/active；父级通过不代表子级通过。
- 验证：运行 `node scripts/validate-theme-isolation.js <项目或文件> <当前主题ID>`，只有 `Result: PASS` 才能交付。

### 文本颜色与背景对比度契约

每个主题都必须同时定义背景和文字角色，而不是只定义主色：

- `--text-primary`：正文、业务数据、表格单元格、表单文字。
- `--text-muted`：辅助说明、次要标签、占位提示；不能低到看不清。
- `--text-on-dark`：深色 Hero、深色卡片、深色导航和深色弹窗上的文字。
- `--text-on-light`：浅色卡片、浅色表格、白色面板上的文字。
- `--text-placeholder`：输入框和搜索框占位文字。

暗色主题（尤其 `cyber-neon`）必须使用浅色正文与浅色次要文字；浅色主题必须使用深色正文与深色次要文字。任何局部背景改变时，都要重新检查局部文字颜色，不能只继承 body 颜色。

验收目标：正文至少 4.5:1，大字号至少 3:1，重要业务数字优先达到 7:1。发现“黑字落在黑底”或“白字落在白底”，直接判定验收失败。

### 组件状态契约

所有可交互组件至少覆盖：默认、hover、focus-visible、active、disabled；表单组件还需覆盖 error；异步区域还需覆盖 loading、empty。动效必须服务于状态反馈，不得阻碍阅读。

### 验收门槛

交付前逐项验证：

- 页面布局和组件骨架发生了与业务语义匹配的改善，而非只换颜色。
- 主题的字体、圆角、阴影、边框、间距、图标和动效保持一致。
- 原有文本、数据、链接、表单和交互没有丢失。
- 1440px、1024px、768px 三档宽度无重叠、截断和横向溢出。
- 键盘焦点清晰；正文与背景保持可读对比度；支持 `prefers-reduced-motion`。
- 与 `demo-<主题ID>.html` 对比时，核心组件形态和视觉气质一致。

## classic-blue-white｜经典·商务蓝白风

### 场景

企业后台、经营看板、运营工作台、工单系统、数据分析和管理系统。目标是提高扫描效率、可信度和任务完成速度。

### 视觉 DNA

- 理性、可信、规整、高信息密度但不拥挤。
- 浅灰蓝页面底、白色业务容器、商务蓝主操作色、深灰标题。
- 6–10px 控件圆角，14–16px 容器圆角；细边框和克制微阴影。
- 中文优先使用 `PingFang SC` / `Microsoft YaHei`，数字使用等宽数字特性。

### 必须重构

- 页面顶部形成“标题/说明 + 时间范围/筛选 + 主操作”工具栏。
- 核心指标形成 3–4 列 KPI 矩阵：标签、主值、同比/环比、迷你进度或说明。
- 普通数据表放入带区块标题、摘要、操作区和分页的业务卡片，不裸放表格。
- 状态统一映射为成功、处理中、警告、失败四类 Badge。
- 有排名语义时使用绩效排行榜；有流程语义时使用服务追溯 Stepper。

### Do

- 对齐网格和列宽；主次操作明确；用蓝色只强调关键动作和当前状态。
- 表格表头、固定列、筛选器、分页器形成统一组件语言。
- 通过留白和字体权重建立层级，不依赖大量颜色。

### Don't

- 不使用大面积高饱和蓝背景；不把每张卡都加重阴影。
- 不使用花哨渐变、玻璃拟态或娱乐化图标。
- 不把所有内容堆成同一种卡片；不把普通列表伪装成排行榜。

### 验收锚点

至少可见：业务工具栏、KPI 矩阵、结构化数据区、统一状态 Badge；整体应明显区别于“原页面换成蓝色”。

## apple-minimal｜Apple 极简高级风

### 场景

品牌官网、产品展示、作品集、高端服务、轻量应用。目标是突出内容、质感和顺滑体验。

### 视觉 DNA

- 大面积留白、极少装饰、强排版、精细层级。
- 黑白灰为主，系统蓝/绿只做功能强调。
- 16–24px 容器圆角、柔和扩散阴影、弱边框或无边框。
- 系统字体栈，标题紧凑，正文舒展，数字清晰。

### 必须重构

- 首屏建立一个明确主叙事：标题、价值说明、主 CTA、视觉焦点。
- 内容以少量大卡片或 Bento 分区组织，减少碎片化小框。
- 数据卡突出数字和趋势，不堆砌标签。
- 开关、分段控件、弹窗和浮层采用 iOS 式克制反馈。

### Do

- 使用一致的视觉节奏、精确对齐和内容优先的留白。
- 用轻微透明度、模糊和阴影表达层级。
- 动画短、柔和、有惯性，但不抢夺注意力。

### Don't

- 不使用硬边框网格、强烈霓虹、粗重投影和大量彩色状态。
- 不把所有按钮做成胶囊；不为了留白牺牲信息可发现性。

### 验收锚点

至少可见：主叙事区、Bento/大卡片层级、克制 CTA、精细控件状态；页面应像重新排版，而不是简单去掉边框。

## pixel-game｜像素游戏风

### 场景

游戏数据、活动运营、年轻化营销、趣味工具、社区挑战。目标是建立强烈世界观和反馈感。

### 视觉 DNA

- 像素字体、3px 深色硬边框、4px 硬边偏移阴影、高饱和 Arcade 撞色。
- 阶梯式或帧式动效，禁止柔滑玻璃质感。
- 信息组件映射为任务、战绩、等级、HP/EXP、奖励和徽章。

### 必须重构

- **登录页/认证页优先重构**：登录页通常拥有最大的空白面积，是主题识别的首要载体。必须将其重构为晴空像素世界，不能只给表单加边框或把左侧改成蓝色渐变。
- 登录首屏至少包含 2–3 朵像素云、草地/土地，以及树木或像素角色中的至少一种；业务标题、说明和登录表单位于清晰的前景层。
- KPI 重构为属性/战绩卡；排行榜重构为英雄公会榜。
- 流程重构为 Quest Stepper；进度映射为 HP/EXP 条。
- 主操作按钮具有实体按键感，按下时阴影位移归零。
- 状态反馈使用像素徽章、提示框和明确音游式视觉节奏。
- React/Vue 页面必须修改 JSX/模板结构并加入主题语义类；仅追加 `index.css` 不算结构重构。

### 业务数据保护

- 云、树木、角色、金币、扫描纹理等装饰层必须 `aria-hidden="true"`、`pointer-events:none`，层级低于表单和数据组件。
- 登录表单、筛选器、表格、分页器、金额、SKU、库存和操作按钮必须处于 `.pixel-business-safe-zone` 或等价的不透明前景容器中。
- 数据密集内页不强制铺满场景装饰；将世界观集中在页头、空状态和区块边缘，避免遮挡列、状态和点击目标。
- 禁止用伪元素覆盖业务容器；装饰不得进入表格滚动区域，不得改变表单可点击范围。

### Do

- 保持像素边缘、有限色板和强状态反馈。
- 用游戏化文案增强结构，但不得改变业务含义。
- 静态页使用 `references/snippets/pixel-login-scene.html`；React 工程先运行 `node scripts/install-pixel-react-assets.js <项目src目录>`，生成可直接导入的 `beautify/PixelLoginScene.tsx` 与 `beautify/pixel-game.css`，再接入原有表单逻辑。
- 先跑验证器记录基线，改造后再次运行并得到 `Result: PASS`。验证未通过时不得宣称主题完成。
- 清理或替换 `rounded-2xl`、`rounded-full`、`blur-*`、`backdrop-blur-*`、柔和阴影、`--glass-*` 和旧主题 Token。

### Don't

- 不使用模糊阴影、玻璃透明、大圆角和丝滑渐变。
- 不让动画持续闪烁影响阅读；不使用低对比像素字体。
- 不把“天空蓝渐变”当作完整晴空场景；没有云彩和地面时不得通过验收。
- 不在业务表格和表单上方放置装饰，也不为了风格改写数据值和业务动作。

### 验收锚点

必须全部通过：

1. 登录页或最大空白首屏能一眼识别为晴空像素世界：晴空、至少 2 朵像素云、草地/土地、树木或角色至少一项。
2. 登录表单和所有关键业务数据无遮挡、可点击、对比清晰；装饰不拦截鼠标。
3. 内页至少出现属性/战绩卡，以及 Quest/HP/EXP 中至少一种语义组件。
4. 主按钮具有硬阴影和按压位移；主要容器使用硬边而非玻璃大圆角。
5. React/Vue 工程的 JSX/模板结构确实被改造，不是只改全局 CSS。
6. 不存在后置旧主题 Token 覆盖当前像素主题，不大量残留 `rounded-2xl`、`rounded-full`、`blur-*`、`backdrop-blur-*`、`--glass-*`。
7. `scripts/validate-pixel-theme.js` 的最终输出必须是 `Result: PASS`，交付回执必须列出实际改动的 JSX/模板文件与构建结果。

任一项缺失都只能报告“像素 Token 适配未完成”，不能报告“像素游戏风已完成”。

## fresh-green｜小清新水晶风

### 场景

个人工作台、健康/生活记录、轻量运营、环保/自然、柔和数据看板。目标是轻盈、舒适、可信。

### 视觉 DNA

- 米白/浅绿背景、薄荷和翡翠强调色、透明水晶卡片。
- 20–24px 舒展圆角、柔和层叠阴影、顶部高光、背景模糊。
- 缓慢极光和漂浮叶片提供氛围，但内容始终清晰。

### 必须重构

- KPI 形成薄荷水晶指标矩阵。
- 核心区域使用透明层级区分，不依赖粗边框。
- 进度和状态使用自然色阶；流程使用轻盈的水晶 Stepper。
- 背景动态装饰必须位于内容后方并禁用指针事件。

### Do

- 使用透明度层级、自然留白和柔和反馈。
- 保证玻璃卡片在复杂背景上仍有足够文字对比度。

### Don't

- 不使用纯白不透明大块遮住背景；不滥用模糊导致性能下降。
- 不使用黑色粗边框、尖锐直角和高频漂移动画。

### 验收锚点

至少可见：水晶 KPI、透明层级、薄荷状态色、柔和背景氛围；不能只是把主色换成绿色。

## cyber-neon｜赛博霓虹风

### 场景

AI 平台、开发者工具、Web3、量化/科技看板、未来感控制台。目标是营造高科技沉浸感，同时保持数据可读。

### 视觉 DNA

- `#080c14` 深空底，电光青、霓虹粉、电光紫做有限强调。
- 暗色面板、细霓虹边缘、切角/科技角标、等宽数字、扫描线和网格。
- 发光只用于边缘、数据和状态，不给所有文字加光晕。

### 必须重构

- KPI 形成量子数据舱；流程形成双色流光 Stepper；告警形成高能赛博 Alert。
- 表格和图表置于暗色控制台容器中，增强列对齐和数字辨识。
- 注入 `<canvas id="cyberCanvas">`、`.cyber-dynamic-bg`、`.cyber-scanline`。
- 注入可运行的粒子脚本：浮动粒子、粒子连线、鼠标吸引、36px 光斑、双层准心和点击火花缺一不可。
- 为触摸设备和 `prefers-reduced-motion` 提供降级；Canvas 必须 `pointer-events:none`。

### Do

- 使用暗底高对比文字；限制霓虹色数量；让动画围绕鼠标和关键状态发生。
- 先保证数据和操作可读，再增加沉浸效果。

### Don't

- 不把扫描线当作完整动态主题；不允许只有 CSS 没有 Canvas JS。
- 不给正文全部加荧光；不让 Canvas 遮挡点击；不使用白底白字。

### 验收锚点

必须全部通过：粒子持续可见；粒子间有连线；鼠标附近有光斑与双层准心；粒子被鼠标吸引；点击产生四色火花；扫描线只是辅助层而非唯一动态效果。

## neomorphism｜Neomorphism 新拟态

### 场景

设置中心、个人控制台、智能家居、健康追踪、音乐控制与低信息密度工具。适合强调“触摸与控制”，不适合超高密度表格系统。

### 视觉 DNA

- 页面与组件使用同一浅灰蓝表面 `#E4E9F0`，层级完全由光影塑造。
- 凸起组件使用右下暗影 + 左上亮影；输入、槽位和按下状态使用双向 `inset` 阴影。
- 圆角集中在 14–22px；只使用一个紫蓝强调色，避免多色破坏柔和感。
- 无硬实线边框，文字仍保持深灰高对比，不能为了拟态牺牲可读性。

### 必须重构

- 普通卡片重构为外凸 Soft UI 表面；输入框、进度槽、开关轨道改为内凹表面。
- 按钮必须具有“抬起 → 悬浮 → 压入”的三态触感，active 时切换为 inset 阴影。
- KPI 卡片使用不同深度表达主次，不允许所有内容处于同一浮层。
- 表格放入外凸业务容器，行分隔保持克制；Focus 使用明显紫蓝光环。

### Do

- 保持统一光源方向和一致阴影距离；让凸起与凹陷形成真实层级。
- 控制低对比面积，同时用深色正文与明确焦点环保证可访问性。
- 把拟态重点放在按钮、输入、开关、卡片和进度槽等“可触摸”组件。

### Don't

- 不使用深色背景、黑色硬阴影、玻璃透明、粗边框或高饱和多色渐变。
- 不给所有文字添加阴影；不让正文与背景对比不足。
- 不把大数据密度后台强行做成完全无边界的新拟态页面。

### 验收锚点

至少可见：同色页面/组件表面、亮暗双向外凸阴影、内凹输入与进度槽、按钮按压 inset 状态、清晰 focus-visible。缺少凸凹层级即判定为“只换浅灰色”，验收不通过。

## retro-y2k｜Retro / Y2K 千禧风

### 场景

时尚、音乐、潮牌、年轻化活动、创作者工具、内容社区和情绪化数据展示。目标是甜美、闪亮、怀旧又面向未来。

### 视觉 DNA

- 粉 `#FF6B9D`、紫 `#C66AFF`、青 `#00D4FF` 构成糖果渐变，白色作为塑料高光。
- Chrome 金属渐变标题、超大气泡圆角、药丸按钮、彩色投影与漂浮圆球共同构成 Y2K 语汇。
- 星芒 `✦/✧` 有节制地闪烁；卡片顶部具有塑料高光，按钮按下时实体下沉。
- 字体圆润而大胆，正文保持可读；不能把 Y2K 简化为普通粉紫渐变。

### 必须重构

- 首屏必须包含糖果渐变焦点区与 Chrome 金属标题或关键数字。
- KPI、卡片和弹层使用白色光泽塑料表面、24–30px 圆角和彩色阴影。
- 按钮、筛选与状态使用药丸形；背景加入不阻塞交互的漂浮气泡和有限星芒。
- 进度条使用粉紫青连续渐变和流动高光；表格仍需保持清晰列结构。

### Do

- 大胆使用粉紫青渐变，但让白色内容表面承担阅读区域。
- 使用 Chrome、气泡、星芒、药丸和塑料高光这组完整语言。
- 动效以慢漂浮、短闪烁和按压反馈为主，并支持减少动态模式。

### Don't

- 不只把主色改为粉紫；不使用直角、纯黑大底或商务灰表格。
- 不做高频闪烁；不让装饰覆盖按钮和正文。
- 不混入像素游戏硬边框，Y2K 的重点是光泽、糖果与怀旧未来感。

### 验收锚点

至少可见：粉紫青糖果渐变、Chrome 标题、白色光泽卡片、药丸按钮、漂浮气泡、闪烁星芒和实体按压反馈。仅有粉紫背景即验收失败。

## claymorphism｜Claymorphism 粘土风

### 场景

儿童产品、教育、任务管理、轻社交、健康习惯、趣味 App 和亲和型运营页面。目标是柔软、友善、可触摸。

### 视觉 DNA

- 超大圆角 20–30px，白色半透明高光边，柔和粉嫩表面。
- 阴影以无模糊的彩色右下位移为主体，可叠加轻微环境阴影，但禁止黑色重阴影。
- 按钮、图标、徽章像软 3D 粘土块，按压时阴影缩短并向下移动。
- 紫、粉、橙承担不同功能色，但整体饱和度柔和、正文保持深色。

### 必须重构

- KPI 和业务卡片必须成为厚实的软 3D 块，使用白色高光边和彩色多层位移阴影。
- 关键图标重构为独立 `.clay-icon` 体积块，不能只放普通线性图标。
- 主次按钮需有清晰体积差异和按压位移；进度条、开关、Badge 保持圆润粘土材质。
- 页面保持舒展留白，避免过多小块导致“糖豆堆积”。

### Do

- 使用无模糊彩色 offset 阴影、多层体积和顶部白色高光。
- 让圆角、图标、按钮、卡片和弹层共享同一软 3D 逻辑。
- 用轻微弹性反馈表达柔软，但运动距离保持克制。

### Don't

- 不使用尖锐直角、黑色阴影、玻璃拟态或霓虹发光。
- 不让所有组件都是相同颜色；不把阴影做成普通柔和投影。
- 不用过度弹跳或果冻形变干扰操作。

### 验收锚点

至少可见：超大圆角、白色高光边、无模糊彩色多层位移阴影、独立粘土图标、按钮压下反馈。仅有粉嫩配色和大圆角即验收失败。
